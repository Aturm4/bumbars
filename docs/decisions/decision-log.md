# Журнал решений

## 2026-08-22

1. Выбран один интерактивный application shell вместо восьми статических страниц: навигация и состояние соответствуют Mini App/PWA.
2. Визуальный язык следует макетам: тёмно-синий ночной фон, графитовые карточки, мшистый зелёный акцент, тёплый кремовый текст и миниатюрные изометрические сцены.
3. Текущий этап — честный frontend simulation slice. Он не имитирует наличие готовой базы или backend.
4. Целевая серверная форма — модульный монолит с PostgreSQL и persistent scheduler.
5. AI и deterministic engine разделены без исключений.
6. Глобальный level исключён; прогресс доменный и evidence-based.
7. Интерфейс и документация ведутся на русском языке; собственные названия и технологии не переводятся.
8. Для развёрнутого серверного вертикального среза выбран D1: это платформенный persistence adapter, а не отмена целевой PostgreSQL-топологии.
9. До подключения постоянной очереди просроченные actions завершаются request-driven reconciliation при чтении состояния. Переход защищён серверным transition token и идемпотентными ledger-записями.
10. Референсы используются только как продуктовый сигнал. Новый UI построен как самостоятельная «панель жизненной навигации» с орбитой ресурсов, маршрутной картой и серверным журналом.
11. Любое платное действие существует в статусе awaiting_confirmation и не списывает деньги до отдельной команды подтверждения.
12. Пункт 3 исторический: frontend simulation заменён каноническим D1 server state; локальные данные используются только как seed мира.
13. Сцена оформлена как самостоятельная настольная экспедиция с бумажной картой и игровыми жетонами; референсы не копируются композиционно.
14. Capacity делится на foreground, background и passive. Занятость персонажа ограничивает запуск действий, но не блокирует игроку интерфейс.
15. Вероятность и RNG являются серверными: сохраняются basis points, seed, roll и исход.
16. Финансовые эффекты вертикального среза переведены на JournalEntry/JournalPosting с равными debit и credit.
17. D1 остаётся adapter прототипа; целевая production-топология PostgreSQL + persistent worker не пересмотрена.
18. Не реализованные production-возможности публикуются в docs/capability-gaps.md и не маскируются моками.

## 2026-08-24

19. После сравнения трёх сгенерированных концептов основой «Квартала» и «Мира» выбран вариант B «настольная кампания»; от варианта A взяты только свет, плотность окружения и ощущение живой сцены.
20. Координата поездки является серверной целью Action и хранится в `action_targets`; текст намерения не используется как источник географической истины.
21. Фишки друзей строятся из настоящих Player, Character и CharacterLocation в D1. UI-константы персонажей запрещены.
22. Внешний AI не имитируется. До передачи API используется `DeterministicDevelopmentProvider` через тот же интерфейс `AiProvider`, который позднее реализует schema-bound OpenAI provider.
23. Карта не меняет позицию оптимистично. Только успешное серверное разрешение подтверждённой поездки обновляет CharacterLocation и посещённость.
24. Неизвестные, небезопасные и ещё не обеспеченные engine/policy возможности не получают декоративных кнопок; они остаются в capability gap registry.
25. Решение 19 отменено на уровне интерфейса: «Квартал» и картографический «Мир» удалены полностью; география, перемещения, участники и world truth остаются каноническими серверными данными для будущих представлений и действий.
26. Информация о мире и других участниках будет вынесена в отдельный преимущественно текстовый раздел. До выбора пользователя реализация не начинается; на утверждение подготовлены A «Хроника», B «Досье» и C «Сводка».
