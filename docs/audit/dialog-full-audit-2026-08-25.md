## Главный вывод

Текущая сборка — серверный демонстрационный срез из пяти каталожных действий. Она доказывает подтверждение, таймер, RNG и ledger, но не реализует центральную механику продукта: свободный непрерывный разговор с ИИ-ведущим, который отделяет вопрос от намерения, строит предложение через детерминированный движок и работает с динамическими сущностями, знаниями, расписанием и последствиями.

## Расхождения, найденные в коде

| Область | Требование источников и последнего запроса | Состояние до переделки | Решение |
|---|---|---|---|
| Разговор с Хостом | Любая реплика: вопрос, обсуждение, уточнение или намерение | Любой текст классифицируется в 5 `ActionKind`; неизвестное — ошибка | Единый Chat API и структурированное решение `conversation / clarification / intent` |
| Поле ввода | Обычный чат без обязательного префикса | «Я хочу…», «Рассчитать», четыре быстрые подсказки | Компактный composer и кнопка-«самолётик» |
| Невозможное действие | Ответ Хоста в истории с понятной причиной | toast `INTENT_NOT_UNDERSTOOD` или техническая ошибка | Канонический in-chat ответ; capability gap без фиктивного действия |
| Деньги | USD и правдоподобные якоря | UZS; тренировка и поездки завышены | Однократная миграция ledger в USD и новый каталог цен |
| Результат действия | Цена, время, риск, затраты и выгоды до подтверждения | Фокус/здоровье; выгоды почти не видны | Отдельные deterministic effects и читаемое резюме результата |
| Обычные действия | Градация качества; тренировка не «проваливается» без причины | Любое действие — бинарный success/failure | `progress` для тренировки/учёбы/медитации, `chance` для рискованных попыток |
| Состояния | Энергия, здоровье, сила, интеллект, мораль, уверенность, усталость | Энергия, здоровье, фокус, мораль, стресс, уверенность, усталость | Удалить фокус/стресс из read-model, добавить силу/интеллект |
| Навыки | Динамические, растут из evidence и повторения | Три статических seed-навыка, завершение их не меняет | Upsert навыка и evidence при разрешении действия |
| План | Сегодняшний план; расписание меняется через Хоста | Ручная форма «Новый ритуал», отдельный список recurring | Только план дня; recurring хранится скрыто и меняется через Chat API |
| Профиль | Настраиваемое имя и возраст | Жёсткий «Алекс» во вкладке и seed | Profile API и форма настроек |
| Организации | Универсальная сущность, появляется только после создания | Nomad Labs присутствует у каждого seed-профиля | Не показывать пустые организации; создание начинается разговором и запросом названия |
| Досье | Только известная персонажу информация и её видимость | Возвращаются истинные локации всех персонажей; ярлыки видимости вычислены индексом | Read-model на базе Knowledge, без утечки World Truth |
| Уведомления | Сообщения, предложения, вызовы; принять, отклонить, ответить | Отсутствуют | Persistent inbox и глобальный колокольчик |
| Динамический UI | Definition + component + generic renderer | Таблицы есть, но read-model и renderer отсутствуют | Добавить DynamicSection в state и ограниченный renderer |
| AI prompts | Constitution + роль + контекст + релевантные versioned playbooks | Один короткий prompt-классификатор | Context Builder, Skill Router для сообщения и versioned playbooks |

## Фазы текущей итерации

1. **Разговор и оркестрация.** Новый `/api/host/messages`, история одного диалога, маршрутизация playbook, свободный ответ/уточнение/намерение.
2. **Детерминированная механика.** USD, реалистичные якоря, расширенные эффекты, логические модели исхода и evidence-based навыки.
3. **Read-model и интерфейс.** Telegram-подобный чат, план дня, настройки профиля, knowledge-safe досье, динамические секции и inbox.
4. **Проверка.** Сценарные smoke-тесты, safety, typecheck, lint, build и визуальная проверка доступными средствами.

## Что остаётся отдельными production-движками

Полноценные market, trade/escrow, organization governance, PvP, investigations/legal, legacy, World Director, Telegram Topics, autonomous NPC и persistent scheduler не могут честно считаться готовыми после одной UI-итерации. В этой итерации создаются их типизированные входы, данные и capability-gap поведение; фактическая мутация денег, вероятностей и прав остаётся только за сервером.
